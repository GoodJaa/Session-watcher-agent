# Session watcher для Claude Code

Сессии Claude Code часто заканчиваются без передачи дел. Вкладку закрыли, ушли на обед,
переключились на другую задачу и контекст остался только в транскрипте, который никто
не читает. Session watcher замечает такие сессии и снимает с каждой короткий ёмкий
**дамп контекста**: цель, что сделано, где остановились, решения, следующий шаг, ключевые
файлы. Дамп получает тег и статус `new`. В новую сессию его загружают явной командой
`/dump-load <тег>`.

- **Автоматически.** Хук `SessionStart` запускает на каждую сессию небольшой фоновый наблюдатель.
- **Дёшево.** Транскрипт сжимается локально в дайджест до ~18 тыс. символов. Затем один вызов
  `claude -p` на Haiku превращает его в дамп: без инструментов, без MCP, без настроек
  и с коротким системным промптом. Один дамп стоит примерно **$0.002–0.005**,
  а сам дамп занимает около 1 тыс. токенов.
- **Только по явной команде.** Дамп сам в сессию не попадает: его загружает `/dump-load`,
  после чего он помечается как `used`.
- **Не мешает вашим ритуалам.** Если у вас есть своя команда завершения сессии
  (например `/handoff`), укажите её в `exclude_commands`. После неё сессия снимается
  с наблюдения, а уже снятый дамп удаляется.
- **Linux, macOS и Windows.** Это один файл на Python 3.8+ без зависимостей. Он использует
  уже установленный `claude` и ваш обычный вход.

## Команды в сессии

| Команда | Что делает |
|---|---|
| `/dump-list [all]` | Таблица дампов текущего проекта (`all` — всех проектов): тег, статус, дата сессии, id сессии, размер префикса, размер дампа, заголовок |
| `/dump-load <тег \| id сессии>` | Загружает дамп в текущую сессию и помечает его `used`. Подходит начало тега или id (от 4 символов), если оно однозначно |
| `/dump-clean [all]` | Удаляет дампы со статусом `used` |

Пример `/dump-list`:

```
| tag             | status | session date     | session id        | resume prefix | dump     | title                   |
|-----------------|--------|------------------|-------------------|---------------|----------|-------------------------|
| `fix-csv-parser`| new    | 2026-10-27 10:02 | `3f2a9c41-…`      | 114k tok      | 0.9k tok | Исправить CSV-парсер    |
| `add-login`     | used   | 2026-10-26 15:40 | `9b07e2d3-…`      | 530k tok      | 1.4k tok | Вход через OAuth        |
```

**resume prefix** — сколько токенов переобработает модель, если вернуться в старую сессию
через `claude --resume`, когда её prompt-кеш уже истёк. Это размер последнего запроса
сессии вместе с ответом, взятый из `usage` в транскрипте. **dump** — примерный размер
дампа. Разница между ними показывает, сколько стоит возврат в сессию по сравнению
с загрузкой дампа.

Вывод скрипта подставляется в команду через `!`-блок, поэтому модель не тратит на него
вызовы инструментов.

## Как это работает

```
хук SessionStart ──► наблюдатель (отдельный процесс, один на сессию)
                       │ раз в минуту читает новые строки транскрипта
                       ├─ встретилась исключённая команда ─► стоп, её дамп удаляется
                       ├─ SDK-сессия / `claude -p` ─► стоп
                       └─ транскрипт не менялся ≥ 50 мин
                             ├─ дайджест (локально): реплики, ответы, правки, коммиты, todo
                             ├─ claude -p --model haiku --tools "" ...  ─► дамп
                             └─ ~/.claude/session-dumps/<проект>/<дата>_<id>.md (status: new) + INDEX.md
```

Если после дампа сессия продолжилась, после следующего простоя дамп обновится:
тег сохранится, а статус снова станет `new`. После 12 часов простоя наблюдатель завершается.
Возобновление сессии (`claude --resume`) запускает новый наблюдатель.

Дамп — Markdown с метаданными в начале файла:

```markdown
---
tag: fix-csv-parser
status: new
session: 3f2a9c41-…
project: /work/app
branch: fix/csv
session_start: 2026-10-27 10:02
session_end: 2026-10-27 11:40
user_turns: 9
resume_tokens: 113668
dump_tokens: 890
model: claude-opus-5-5
dumped: 2026-10-27 12:31
used_at:
used_in:
---

# Исправить падение CSV-парсера на переводах строк в кавычках

## Goal
## Done
## State when stopped
## Decisions and facts
## Open / next step
## Key files
## Working tree at dump time
```

Заголовки разделов всегда на английском, а текст — на языке сессии (см. `language`).
`used_at` и `used_in` заполняет `/dump-load`: время загрузки и id сессии, куда загрузили дамп.

## Установка

Linux и macOS:

```bash
git clone https://github.com/GoodJaa/Session-watcher-agent.git
cd Session-watcher-agent
python3 install.py                 # все проекты: хук в ~/.claude/settings.json, команды в ~/.claude/commands/
```

Windows (PowerShell или Git Bash):

```powershell
git clone https://github.com/GoodJaa/Session-watcher-agent.git
cd Session-watcher-agent
py install.py
```

Частые варианты:

```bash
python3 install.py --exclude handoff                   # эта команда снимает сессию с наблюдения
python3 install.py --dumps project                     # дампы в <проект>/.claude/session-dumps/
python3 install.py --settings ~/work/app/.claude/settings.local.json   # только один проект
python3 install.py --uninstall                         # убрать хук и команды, дампы остаются
```

Установщик делает следующее:

- копирует `session_watcher.py` в `~/.claude/session-watcher/` и создаёт там `config.json`;
- добавляет хук в файл настроек, предварительно сделав его резервную копию. Хук записан
  в exec-форме (интерпретатор и аргументы без shell), поэтому одинаково работает
  с bash, zsh и PowerShell;
- кладёт `/dump-list`, `/dump-load` и `/dump-clean` в каталог `commands/` рядом с файлом
  настроек. Команды с такими же именами, созданные не установщиком, он не трогает.

Повторный запуск заменяет хук, а не добавляет второй. Наблюдаются только сессии, запущенные
после установки. Если Claude Code работает с `CLAUDE_CONFIG_DIR`, всё ставится туда вместо `~/.claude`.

## Настройка

Файл `~/.claude/session-watcher/config.json`. Все ключи необязательны. Любой из них можно
задать и переменной окружения `SESSION_WATCHER_<КЛЮЧ>`, например `SESSION_WATCHER_IDLE_MINUTES=30`.

| Ключ | По умолчанию | Назначение |
|---|---|---|
| `idle_minutes` | `50` | Сколько минут простоя до дампа |
| `model` | `haiku` | Модель для дампа (значение `--model`) |
| `exclude_commands` | `[]` | Префиксы имён slash-команд и skill, которые снимают сессию с наблюдения. Например, `"handoff"` покрывает `/handoff`, `/handoff-now`, `Skill handoff`, `/plugin:handoff` |
| `dumps_dir` | `~/.claude/session-dumps` | Корень для дампов, по папке на проект; `"project"` пишет в `<проект>/.claude/session-dumps/` и добавляет его в `.git/info/exclude` |
| `language` | `auto` | Язык дампа; `auto` — язык сессии |
| `max_words` | `350` | Предел длины дампа |
| `max_digest_chars` | `18000` | Предел того, что уходит в модель |
| `keep_days` | `60` | Дампы, не менявшиеся дольше этого срока, удаляются |
| `projects` | `[]` | Наблюдать только сессии в этих каталогах (пусто — все) |
| `skip_entrypoints` | `sdk-cli`, `sdk-ts`, `sdk-py`, `sdk` | Неинтерактивные сессии, которые никогда не наблюдаются |
| `give_up_hours` | `12` | Через столько часов простоя наблюдатель завершается |
| `claude_bin` | авто | Путь к `claude`, если автопоиск не справился |

`claude` ищется в таком порядке:

1. процесс, запустивший хук, и `CLAUDE_CODE_EXECPATH`;
2. `PATH`;
3. `~/.local/bin` и `~/.claude/local`;
4. каталоги расширений VS Code, Cursor и Windsurf (`claude.exe` на Windows).

## Windows

- Наблюдатель запускается без окна, в отдельной группе процессов и вне job-объекта
  Claude Code, поэтому переживает закрытие сессии. Блокировка сессии сделана через `msvcrt`,
  проверка живости процесса — через WinAPI.
- Хуку shell не нужен.
- Slash-команды выполняют `!`-блок в shell, который Claude Code использует для команд
  (на Windows это Git Bash). Пути в командах записаны с прямыми слэшами и в кавычках.
- Тесты в CI проходят на Windows, macOS и Linux.

## Служебные команды

```bash
W=~/.claude/session-watcher/session_watcher.py
python3 $W status                              # наблюдаемые сессии и их состояние
python3 $W list all                            # то же, что /dump-list all
python3 $W dump --transcript <файл.jsonl>      # снять дамп сессии сейчас
python3 $W dump --transcript <файл.jsonl> --dry-run   # только показать дайджест, который ушёл бы в модель
tail ~/.claude/session-watcher/watch.log       # что происходило, с расходом токенов на каждый дамп
```

Транскрипты лежат в `~/.claude/projects/<slug-проекта>/<id-сессии>.jsonl`.

## Приватность и расход

Каждый дамп отправляет дайджест транскрипта в модель через ваш собственный вход в `claude`.
Это тот же провайдер, с которым уже работала сессия, больше данные никуда не уходят.
В дайджест не попадают вывод инструментов, размышления модели и системные напоминания.
В нём остаются ваши сообщения, ответы ассистента и короткие строки о действиях: пути
к файлам, описания команд, отметки коммитов, todo-список. Токены и стоимость каждого
дампа пишутся в лог.

## Ограничения

- Простой считается по времени изменения транскрипта. Одна команда, которая молча
  работает дольше `idle_minutes`, сойдёт за простой.
- Сессии, уже запущенные к моменту установки, не наблюдаются. Наблюдение начнётся
  при их следующем запуске или возобновлении.
- Для хука в exec-форме (`command` + `args`) нужна свежая версия Claude Code.
